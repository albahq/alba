# Alba Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Alba's core: the Beamfile DSL (lexer, parser, diagnostics), the project model with imports and DAG validation, the parallel tokio scheduler, a system-shell executor behind the `Executor` trait, and the headless CLI.

**Architecture:** Cargo workspace, modular monolith, single `alba` binary. Strict downward dependencies: `alba-cli` → `alba-engine` → `alba-core` → `alba-syntax`; `alba-engine` sees executors only through the `Executor` trait defined in `alba-executors`. A single event channel carries execution events from the engine to the renderer.

**Tech Stack:** Rust (edition 2024, stable toolchain), tokio, miette (diagnostics), thiserror, clap (CLI), insta (snapshots), assert_cmd + tempfile (end-to-end tests).

**Spec:** `.claude/superpowers/specs/2026-07-27-alba-core-design.md`

## Global Constraints

- Workspace crates for this sub-project: `alba-syntax`, `alba-core`, `alba-engine`, `alba-executors`, `alba-cli`. No other crates yet.
- Dependency direction only downward: `cli` → `engine` → `core` → `syntax`; `engine` → `executors`. Never the reverse, never sideways into `cli`.
- TDD for every task: failing test first, minimal implementation, green, commit.
- Commit messages: gitmoji + Conventional Commits (`✨ feat(syntax): ...`, `✅ test(engine): ...`). No Claude attribution anywhere.
- All code, comments, and documentation in English.
- Exit codes: 0 success, 1 beam failure, 2 Alba error (parsing, configuration).
- `inputs`/`outputs` and `executor docker { ... }` must parse; `inputs`/`outputs` are inert; `executor docker` fails at run time with "docker executor is not yet supported".
- Must compile and pass tests on macOS, Linux, Windows (CI matrix).
- Error diagnostics carry source spans; error message texts are snapshot-tested.

**Interfaces:**

Comments start with `#` and run to end of line. Newlines are tokens (statement separators); consecutive newlines collapse to one. Both `"..."` and `'...'` delimit strings.

```rust
pub struct Project { pub beams: Vec<Beam>, pub default: Option<BeamId> }
pub struct BeamId(pub String);          // fully namespaced: "api:build" or "build"
pub struct Beam {
    pub id: BeamId,
    pub description: Option<String>,
    pub needs: Vec<BeamId>,

    pub inputs: Vec<String>,            // evaluated but inert in this sub-project

}
pub enum Value { Str(String), Bool(bool) }
pub fn eval_expr(expr: &Expr, scope: &Scope) -> Result<Value, CoreError>
pub fn render_template(t: &StringTemplate, scope: &Scope) -> Result<String, CoreError>
```

```rust
pub struct RunOptions {
    pub jobs: usize,                    // semaphore size
    pub keep_going: bool,
    pub params: Vec<String>,            // positional args for the target beam
}
pub enum RunEvent {
    BeamStarted { id: BeamId },
    BeamOutput  { id: BeamId, line: OutputLine },
    BeamFinished { id: BeamId, status: BeamStatus, duration: Duration },
    RunFinished { summary: RunSummary },
}
pub enum BeamStatus { Succeeded, Failed { exit_code: i32 }, FailedAllowed { exit_code: i32 }, Cancelled }
pub struct RunSummary {
    pub succeeded: Vec<BeamId>, pub failed: Vec<BeamId>,
    pub failed_allowed: Vec<BeamId>, pub cancelled: Vec<BeamId>,
    pub duration: Duration,
}
impl RunSummary { pub fn exit_code(&self) -> i32 { if self.failed.is_empty() { 0 } else { 1 } } }

pub async fn run(

    target: &BeamId,
    options: RunOptions,
    executor: Arc<dyn Executor>,
    events: tokio::sync::mpsc::UnboundedSender<RunEvent>,
    cancel: CancellationToken,
) -> Result<RunSummary, EngineError>
```

Scheduling rules (from spec): one tokio task per beam in the subgraph; a beam waits for all its `needs`, acquires a semaphore permit (`jobs`), renders its `run` templates with params in scope, executes each command sequentially (stop at first failure), releases the permit. Fail-fast: a `Failed` beam (not `FailedAllowed`) marks all not-yet-started beams `Cancelled` unless `keep_going`; a beam whose dependency ended `Failed` or `Cancelled` becomes `Cancelled` (never runs) even with `keep_going`; `FailedAllowed` counts as satisfied for dependents. Beam params: only the target beam may declare params in this sub-project; passing params to a target without params (or missing required params) is an `EngineError`. Multi-command `run` emits one `BeamStarted`/`BeamFinished` pair (commands are internal). Docker executor kind → `EngineError: "docker executor is not yet supported"` before any execution starts.
